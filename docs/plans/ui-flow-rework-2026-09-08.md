# 桂桂交互重构计划:验证器中心化 + 错误路由统一(2026-09-08)

> 起因:用户判定「交互混乱的主因 = 容错/出问题的显示/引导/应该打开哪个页各自为政」。
> 本计划把所有容错收进一张**错误路由总表**,新增**验证器(诊断)作为一切问题的第一处理点**,
> 反馈降级为「验证器处理不了的问题」的兜底出口;成功语义收敛为「全验证通过(彩带)」或
> 「诚实的保存配置(不撒彩带)」两种,消灭"半个成功"。
> 用户已逐条拍板(见 §9 决策记录);标注 ⚠ 的 4 处为执行默认,可被用户一句话推翻。

## 0. 总纲(本次重构的中心思想)

1. **完成是全有或全无**:登录真验证通过 + 定时任务在岗 = 成功(彩带);否则不叫成功。
2. **客观验不了(不可达/门没开/注销无效)→ 统一叫「保存配置」终态**,文案明说「连上后自动执行」,不冒充登录成功、不撒彩带。
3. **断网统一归 v-guide**(任何视图 + v-boot 开机探测,收到不可达即跳,不留在原地)。
4. **出问题先找验证器**(新诊断页,逐步探测链路可见);验证器兜不住的才进反馈页。
5. **每类错误只有一个去处、一个明确动作**(§1 总表),容错代码不许自由发挥。

## 2. 验证器(诊断)设计 — 新页 v-diag + 后端 diagnose()

### 2.1 步骤链路(每步 UI:名称 + 进行中转圈 → ✓通过 / ✗失败+人话原因+出口)

| 步骤 | 检查内容 | 依赖(现有/需新增) | 失败出口 |
|---|---|---|---|
| S1 程序自身 | 后端桥接活着(前端 GG.mode 可自测)/ 配置文件可读写 / 凭据保险库可用 / 近 7 天崩溃记录 | config、vault 已有;**crashlog 摘要需新增暴露**;桥接前端自测 | 程序问题 → 重启提示 / 反馈 |
| S2 自动化在岗 | Windows 任务计划服务可用 / 4 拍任务在岗(按配置只查该存在的) | scheduler 已有 | 任务被拦 → v-success 拦截版(重建) |
| S3 网络连通 | 网卡/WiFi 连接状态 / 能否连 10.1.2.3(chkstatus 80 端口) | wifictl、detect.probe 已有 | 连不上 → v-guide(挑网/等网/保存配置) |
| S4 认证验证 | 在线:chkstatus 只读核对线上学号(本人/他人/他人→换会话告知);未登录且已存凭据:真登一次(密码裁判) | drcom.chkstatus_uid、login 已有 | 密码/学号被拒 → **直说结论**(「密码被服务器拒了」)+「去改密码」→v-login |
| S5 汇总报告 | 全绿=「一切正常」回主页;任一红=该步出口前置 | 前端聚合 | 兜不住 → 反馈页 |

**安全约束(写死)**:在线状态**绝不试登**(会注销现有会话断网几秒),只做只读核对;只有未登录时才用已存凭据真登验证。

### 2.2 契约变更(升 1.5.0)

- 新增 `diagnose()` → 串行执行 S1–S4,期间推 `diag:step` 事件 `{step, state: running|pass|fail, detail, exit?}`,结束返回汇总 `{all_ok, exits[]}`。
- `login()` 信封重审:`stored`(锚前)与降级存入路径的语义改为「保存配置」——result 枚举保留但前端按新终态呈现;`already` 不再当成功彩带(在线且本人=正常,无需庆祝)。
- 其余方法不动;`taskStatus()` 保留(诊断 S2 复用)。

### 2.3 v-diag 页面(新视图)

- **入口**:v-guide「启动排查」/ 主页「再登一次」连续失败横幅 ⚠A / 主页任务被拦横幅 ⚠D / 设置页(若保留入口)。
- **结构**:标题「让桂桂查一查」+ 步骤链路列表(五步,逐步点亮)+ 汇总出口区(按失败步给按钮,文案直说诊断结论)。
- 命名与标题文案 ⚠C(默认「一键排查 / 桂桂体检」风格,执行时出两稿给用户挑)。

## 3. 逐页改动明细

### v-guide(不可达排查,保留定位)
1. 标题左边加 bot + 状态表情(不可达=cry),与其他页 .greet 布局一致。
2. 状态栏「10.1.2.3 · 不可达」琥珀加强(Q9/B:加深底色+警示图标,与主页 down 态区分)。
3. ②「重新检测」→「启动排查」:点击进 v-diag(不再是原地 probe;现有 reProbe 死功能嫌疑的根因=无反馈,由诊断页的逐步链路彻底解决)。
4. ③「先填资料,连上后桂桂自动帮你登录」→「保存配置」流:文案改为「先把配置存好,连上后自动执行登录」;由此路径进入的表单提交按钮=**「保存配置」**;保存后进 v-success 保存终态:「配置保存成功!连上校园网之后自动执行登录」(不彩带)。

### v-ok / v-login(表单页)
1. 警告统一:密码空/被拒/节流全部用 **B 基准暖色块**(密码框下方,v-ok 现样式),v-login 的 login-err 细行删除换组件;两页同位置同样式。
2. **删换学号确认框**(login-confirm 整块 + confirmUidChange 逻辑);后端 rekey 迁移静默执行,靠验证器当场自纠。
3. 停留时收到 unreachable → **直接跳 v-guide**(撤上一轮「只刷状态行」方案;返回后表单数据保留)。
4. 提交按钮文案随来路:可达验证流=「立即登录」;v-guide③ 保存流=「保存配置」。

### v-success(终态收敛,只剩两种)
1. **全验证通过**(verified=true + task_ok=true):现彩带页。
2. **保存配置**(不可达存/锚前存/降级存):不彩带,bot 平静表情,文案「配置保存成功!连上校园网之后自动执行登录」;锚前变体文案「校园网 06:50 开门,开门后自动验证登录」。
3. **拦截版**(登录成功但任务被拦):去掉「完成,回主页」按钮,只留「重建定时任务」;重建成功**且**验证通过(该路径登录已验过→重建成功即达)→ 重渲为彩带页;bot 表情 sad;重建失败就地提示可重试。
4. 删除 before_open / unverified 独立变体(并入保存终态);`already` 不再进庆祝页。

### v-main(主页收敛)
1. 状态四种:正常(问候)/ 掉线 out(标题「呜,刚才掉线了」+ 按钮**「再登一次」**)/ 不可达 down(按钮「去排查」→ v-guide)/ 桂桂睡觉(master off)。
2. 「再登一次」:成功=就地反馈(现状);被拒=**跳 v-login**;不可达=跳 v-guide(现状)。
3. 连续失败(默认≥2 次)→ 横幅「还是不行?让桂桂查一查」→ v-diag ⚠A。
4. 横幅只剩两类:「密码还没验证过」(仅保存配置路径)+「自动登录还没生效」(任务被拦,→ v-diag ⚠D);「今早没登上」横幅删除。

### v-feedback(终态页)
1. 发出且收到 → 终态页(成功,bot happy):「收到啦,谢谢你(凭据号 GG-37)」**工单号在文案区** + 完成按钮。
2. 没发出(queued)→ 终态页(沮丧,bot sad):标题「暂时没发出去,已存本地」+ 两按钮:次级「立刻重发」(**回反馈页且刚填的内容保留**)、黑主按钮「完成,等待自动补发」。
3. 草稿保留实现:queued 后不清空表单;点「完成」时把草稿留在表单(补发成功后清)。

### v-boot(开机)
1. 探测不可达(首装+日常)→ **直接跳 v-guide**(日常目前落主页 down,改为跳);仪式照播。
2. BRIDGE_MISSING 态保留(明说重启/重装)。

### v-settings
1. **删任务被拦行**(task-row):信息归主页横幅 + 诊断页 S2 出口。
2. 其余不动。
