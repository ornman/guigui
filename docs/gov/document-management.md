# 文档管理法(目录宪法)

> 治理文档之一。回答三个问题:**什么文档放哪、谁是某件事的正本、文档怎么生老病死**。配套:SPEC §5 文档地图(入口)、`docs/gov/sdlc.md`(何时产出哪类文档)。

## 1. 目录宪法

| 目录 | 定位 | 命名法 |
|---|---|---|
| `docs/SPEC.md` | 项目总纲(常青) | 固定名 |
| `docs/gov/` | 治理:流程/文档法/模板/ops(常青) | `<主题>.md`,不带日期 |
| `docs/prd/` | 产品语义正本(常青):PRD、状态矩阵、反馈系统 | `guigui-<域>.md`;流程图产物入 `flows/` |
| `docs/tech/` | 技术方案 + 审计 + 测试床记录(快照) | `guigui-<域>-<类型>-YYYY-MM-DD.md`;契约例外:固定名 `guigui-bridge-api-v1.md` |
| `docs/adr/` | 架构决策记录(快照) | `NNNN-slug.md` 编号递增,不改号不复用 |
| `docs/plans/` | 执行计划(快照)+ roadmap(常青) | 计划 `<主题>-YYYY-MM-DD.md`;roadmap 固定名带年月 |
| `guigui/app/static/dev/` | mock(可执行契约规范,仅开发) | — |
| `dev/` | 开发期工具与验收 runner(不进产品包) | — |
| `legacy-v1/` | v1 全档 | **冻结只读**,任何改动禁止 |

## 2. 常青 vs 快照(本管理法的核心二分)

- **常青文档**(SPEC、gov/*、PRD、矩阵、契约、roadmap):描述「现在是什么样」。改了立即生效,靠 git 历史留痕,**不写「更新日志」进正文**(契约的「变更记录」节是它的例外正本职责)。
- **快照文档**(plans、tech 审计、ADR):记录「当时怎么想/怎么干」。**落盘即历史,永不改写内容**;只允许两种追加:头部状态行(如「已闭环」)和文内明确标注的回填节(如 ADR-0002 的 spike 结论回填)。
- 判断法:这份文档说的话过半年还应该为真吗?是 → 常青;否 → 快照。

## 3. 单一正本规则(同一事实只在一处维护)

| 事实 | 正本 | 其他地方怎么办 |
|---|---|---|
| 前后端接口/信封/错误码 | 契约 docs/tech/guigui-bridge-api-v1.md | mock.js 是可执行规范,改接口先改契约再同步 mock |
| 任务拍名/触发器语义 | `guigui/core/scheduler.py` | 矩阵、白板 DSL 引用时同步 |
| 视图×状态的用户可见行为 | docs/prd/guigui-state-matrix.md | 改行为的 PRD/代码必须同步矩阵(同步义务) |
| 产品拍板与理由 | PRD 相应章节(产品)/ ADR(技术取舍) | SPEC §4 只存一行结论 + 指针 |
| 跨会话记忆(方法论/环境/教训) | agent 记忆目录(MEMORY.md 索引) | 不入 docs(docs 是项目资产,记忆是 agent 的) |
| 已知工程坑 | docs/gov/ops.md §坑表 | 新坑先入表,防止每次重踩 |
| 版本号 | setup.iss AppVersion | 发布产物名随之 |

**反例警示**:契约版本曾在 ADR/审计/索引里多处转抄(279/303/322),数字漂移已经发生过一次(ADR-0001 写 279,实际 303)。转抄必须写「见 <正本>」而不是复制数字。

## 4. 生命周期

```
草稿 → 生效 → 已闭环/已接受/已否决 → (物理不挪,只标状态)
```

1. **草稿**:标题行加 `(草稿)`;不进索引。
2. **生效**:进对应索引(SPEC 文档地图 / adr README / plans 由 roadmap 挂账)。
3. **收口**:计划执行完 → 头部加「已闭环(日期,commit 链)」;ADR → 状态行改已接受/已否决;审计 → 风险清零或挂 roadmap。
4. **归档 = 标注,不是移动**:不物理挪目录(会断链接),历史永不删除。

## 5. 新文档落盘检查单(提交前过一遍)

- [ ] 放对目录了吗(§1 宪法)?
- [ ] 常青还是快照分对了吗(§2)?快照文档会不会被误当现状引用?
- [ ] 有没有复制了别人的正本内容(§3)?改为指针。
- [ ] 常青文档进索引了吗(SPEC §5 / gov 内互链)?
- [ ] 计划类文档带「执行约定」节 + 收口时补状态了吗?
- [ ] git commit 信息说清「改了什么、为什么」了吗(AGENTS.md 规范)?
