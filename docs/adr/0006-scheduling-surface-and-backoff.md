# ADR-0006:调度暴露面收敛——Wake 降级语义 + 对齐退避

- **状态**:提议(**含两项轻拍板:用户可见文案、停试语义**;文案过目走场景化清单流程)
- **日期**:2026-09-11
- **关联**:审计 R6 / S3;不推翻 2026-09-07「计划任务机制不动」拍板

## 背景

两个同源的架构缺口:

1. **Wake 任务被拒无降级路径**:selfheal.py:44-52 的降级只认 LogonTrigger(去掉重注册);`GuiGui-Wake`(EventTrigger)被安全软件拒掉后 misaligned 常亮,**没有任何收敛手段**——EventTrigger 去掉即空任务,「降级注册」语义不存在。
2. **reconcile 无退避**:GUI 启动(gui.py:290-311)、每次 saveConfig(api.py:538-541)、masterToggle、rebuildTask 3 连轮(api.py:589-593)都会全量重试建任务。在拦截环境下:每次保存设置 = 向杀软再交一次 4 任务建单;rebuildTask 3 连轮在几秒内打 12+ 次 schtasks/COM——既是行为噪音,也让「被拦」状态永远等不到用户处理就重试。

ADR-0001 换传输层后拦截概率下降,但「任务被事后删除/拒绝」场景仍在,无退避的重试照样空转。

## 决策

1. **停试 + 显式恢复**:同一任务连续 3 次 reconcile 建立失败 → 该任务进入 `degraded` 停试(记入 ensure_state,新增键 `wake_degraded`/通用 `task_fail_streak`,向后兼容),不再随 saveConfig/启动自动重试。
2. **恢复入口 = 用户动作**:设置页「点此重建」(rebuildTask)无条件全量重试并清零计数——与既有拍板「rebuild 仅用户点击触发,绝不静默进程重建」(契约 §2.14)同语义,把「何时再试」的决定权交还用户。
3. **信封带出**:taskStatus 增列降级状态,前端设置页「定时任务」行如实显示「唤醒补登录暂不可用(需重建)」类文案——**文案拟稿过目后实施**。
4. patrol 默认 30 分钟(boot/wake/patrol 默认面已保守,config.py:70-78)——**不调**,本 ADR 不动默认值。

## 拍板点(呈报用户)

- 停试阈值 3 次是否合适(1 次太神经质,3 次是建议值);
- 停试后用户可见文案(横幅/设置页行)——走场景化文案清单流程。

## 后果

- 正向:拦截环境下行为噪音骤降;misaligned 状态从「永远重试」变「如实降级 + 等用户」;
- 负向:ensure_state +1 键(schema 演进,向后兼容已核:load_state 对未知键宽容);用户多一种可见状态(文案负担 +1,靠去重与过目控制)。

## 实施清单(文案过目后执行)

1. `selfheal.py`:_align 记录连败计数(读/写 ensure_state);达阈值跳过重建并置 degraded。
2. `api.py`:taskStatus 信封加 degraded 字段;rebuildTask 清零逻辑。
3. 前端:设置页定时任务行降级态渲染(文案定稿后)。
4. 测试:279 基准;新增「3 败停试 / rebuild 清零 / 旧 state 无新键不炸」单测;mock 场景加「拦截→降级→重建恢复」链。
5. 契约:taskStatus 信封扩展属向后兼容新增,契约 minor bump 并记变更。

## 验证基准

同 ADR-0001;F 章动态验收补「停试/恢复」场景帧。
