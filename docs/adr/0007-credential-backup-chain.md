# ADR-0007:凭据备份链(库链)——DPAPI 加密备份 + 静默切换

- **状态**:提议·设计草案(2026-09-12 用户拍板「要做,自动切换不弹通知」;本文件为设计方案,**过目后实施**)
- **日期**:2026-09-12
- **关联**:契约 1.6.0 缺口清单第 1/2/3 组(ui-interaction-rework G 章);vault.py 现状;ADR-0006(降级可见性同族)

## 背景

密码唯一存于 Windows 凭据管理器(vault.py:keyring 主路 + advapi32 直调)。若该条目被安全软件"清理"、系统抽风损坏或用户误删,`get_password` 返回 None → ensure 整拍静默跳过(ensure.py:327-330),「每天 07:00」的承诺无声死亡。白板故障带为此画了 vault/degrade 节点(备份库 JSON、自动重建、降级🔔),挂「待 1.6.0 拍板」。

**2026-09-12 用户拍板**:库链做;**自动切换时不弹通知**(与白板原案的降级🔔不同,以用户拍板为准)。

## 决策(设计草案)

1. **备份内容与位置**:仅备份凭据本身(uid + password);落 `%LOCALAPPDATA%\GuiGui\vault.bak.json`(数据目录内,随卸载问询一并处理)。config.json 不需要备份(自身已原子写)。
2. **加密 = DPAPI**(crypt32 `CryptProtectData`,当前用户 scope,ctypes 直调,零新增依赖):
   - 与凭据管理器同一信任模型(同用户隔离、无密钥管理问题);
   - 红线继承:备份文件是密文,满足「密码永不落明文」;日志/诊断包永不包含其内容。
   - **不选**:自造 AES(key 存放必成新弱点)、明文(违红线)。
3. **写入时机**:`set_password` 主路成功后同步写备份(主→备顺序);改学号 rekey 时备份随迁;写备份失败只记日志不阻断主流程(下次保存再试)。
4. **静默切换(failover)**:`get_password` 主路拿不到、且备份可解密 → 用备份供血当拍登录,并**静默回写主库**(自愈回主路);回写失败重试 ≤3 次(每拍一次),仍失败则持续备份供血。**全程不发通知**(用户拍板);`ensure_state` 记 `backup_failover: true`,经 taskStatus/巡检信封带出,**状态页可见**。
5. **双库皆坏 / 从未配置**:回落现状语义(视为未配置,首装流程),不造数据。
6. **契约**(随批A一并 bump):巡检只读方法或 taskStatus 扩展带 `backup_ok / failover` 布尔——状态页数据源;不新增通知种类。

## 替代方案(为何不选)

- **只检测不备份**(降级🔔原案):用户已否——要的是自动续命,不是多一条通知。
- **备份进注册表/另一凭据条目**:同库相关性高(安全软件清理往往一起清),JSON 文件 + DPAPI 独立性更好。
- **明文备份**:违 SPEC §2 凭据红线。

## 后果

- 正向:凭据管理器单点死亡面消除;静默续命 + 状态页如实可见(符合「降级不出声、状态要透明」的组合拍板)。
- 负向:密码多一处落盘形态(DPAPI 密文,风险可控);主备一致性维护(rekey/保存路径各 +1 步);测试面新增(备份读写/failover/回写重试)。

## 实施清单(过目后执行)

1. `vault.py`:DPAPI 加解密 ctypes 封装、备份读写、failover + 回写重试;`set_password` 挂备份写入。
2. `ensure.py`:凭据获取走 failover 语义;state 记 `backup_failover`。
3. 契约 bump(与批A 同次):状态字段带出;前端状态页降级行渲染(文案入 H 表场景化清单)。
4. 测试:备份往返/损坏备份/主库失联 failover/回写重试上限/明文永不落盘(红线断言)/rekey 迁移;基线 326 只增不减。
5. 诊断包:仅布尔状态,不含备份文件本体。
